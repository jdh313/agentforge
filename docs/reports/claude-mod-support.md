# Claude mod support (function-hook modules)

Handoff from a jdh-agents session: let a package enrolled for both Claude and
Codex ship a Claude Code "mod" (`hooks/hooks.json` = `{ "modules": [...] }`
plus a `types` declaration) without Codex receiving any of it.

## Design

**Chosen: `hook-module` as a declared-loss construct, not target-scoped
artifacts.**

- Codex's hook parser now accepts a document with `hooks`, `modules`, or both.
  The `modules` key is detected as the Claude-only construct `hook-module`
  (`src/compatibility.ts` `pushHookModules`).
- Codex hooks are shell commands only, so `modules` is a silent loss. Under the
  declared-loss gate (ndr:728mf7) an undeclared one fails compilation naming
  `hooks/hooks.json:<line>`. The declared `state` is checked against emitted
  output (ndr:b71vq2) through a new `json-key` retention check: a modules-only
  document emits nothing, so the state is `stripped`. A mixed document keeps
  its classic events on Codex and drops only `modules`.
- Why not target-scoped artifacts: scoping the artifact away from Codex would
  drop the mod with nothing on the record. The loss gate exists so a confirmed
  loss is declared once and reported on every compile (ndr:62pj9p). It also
  catches the next package that adds a mod without thinking about Codex.
  `register.ts` and `types/index.d.ts` stay Claude-only through
  `targets.claude.payloads`, which already worked.
- `types`: the brief's failure #2 did **not** reproduce. `targets.claude.native.types`
  already reached `plugin.json` in both 1.2.0 (pinned binary) and source.
  What was missing was validation. `ClaudePluginManifest` now types `types` as a
  string, and compilation fails unless it is `./`-relative, does not escape the
  plugin, and names a file the package ships on Claude
  (`src/targets/claude-marketplace.ts` `assertTypesShipped`).

Docs: README `targets.<name>.losses` construct list and a `native.types`
bullet. CHANGELOG is generated by semantic-release from the commit, so it is
not edited by hand.

## Release and pin bump

1. Push `main` to `origin`, then to `github`. `github/main` is at v1.2.0, and
   `origin` already holds unreleased `feat:` commits (sync-codex-agents, the
   role-check hook). semantic-release will therefore cut **v1.3.0** and attach
   the darwin-arm64, linux-arm64, and linux-x64 binaries plus `SHA256SUMS`.
2. In jdh-agents `scripts/agentforge.sh`: set `AGENTFORGE_VERSION="1.3.0"`,
   and replace the three hashes in `sha256_for` with the v1.3.0
   `SHA256SUMS` entries.
3. In jdh-agents `plugins/linear/PACKAGE.yaml`: add `native: {types: ./types/index.d.ts}`
   under `targets.claude`, and add the `hook-module` loss under
   `targets.codex.losses`.
4. Run `scripts/agentforge.sh compile MARKETPLACE.yaml --out marketplaces`,
   then `check ... --claude-native`, and commit the regenerated tree.
